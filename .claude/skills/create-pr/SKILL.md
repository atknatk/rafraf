# /create-pr

> Feature branch'ini push et ve Pull Request olustur.

## Kullanim

```
/create-pr
/create-pr --pipeline full
/create-pr --base develop
/create-pr --draft
```

**Parametreler**:
- `--pipeline`: Pipeline tipi (`full`, `standard`, `quick`). Otomatik algılanır.
- `--base`: Hedef branch (varsayilan: `develop`)
- `--draft`: Draft PR olustur

## Calisma Adimlari

### Adim 1: Mevcut Branch'i Analiz Et

```bash
CURRENT_BRANCH=$(git branch --show-current)
echo "$CURRENT_BRANCH"
```

Branch'in `feature/f<FAZ>/<ISSUE_NO>-<slug>` formatinda olup olmadigini kontrol et.

Branch'ten bilgileri cikar:
- **Faz**: `f<FAZ>` kismi -> FAZ numarasi
- **Issue No**: `<ISSUE_NO>` kismi
- **Slug**: `<slug>` kismi

Ornek: `feature/f1/42-chat-ekrani-websocket` ->
- Faz: 1
- Issue: 42
- Slug: chat-ekrani-websocket

### Adim 2: Commit Kontrolu

```bash
# develop'dan bu yana commit var mi?
git log --oneline develop..HEAD
```

Eger 0 commit varsa hata ver: "PR olusturmak icin en az 1 commit gerekli."

### Adim 3: Branch'i Push Et

```bash
git push -u origin "$CURRENT_BRANCH"
```

Push basarisizsa:
- Remote branch zaten varsa: `git pull --rebase origin "$CURRENT_BRANCH"` sonrasi tekrar push
- Authentication hatasi: `gh auth status` ile kontrol et

### Adim 4: Issue Bilgilerini Cek

```bash
gh issue view <ISSUE_NO> --json title,body,labels --repo atknatk/rafraf
```

Issue'dan:
- **Title**: PR basliginda kullanilacak
- **Labels**: Pipeline tipi, katman, faz bilgileri

**Type belirleme**: Issue title ve icerigine bak. Yeni ozellik: `feat`. Hata duzeltme: `fix`. Yeniden yapilandirma: `refactor`. Scope: issue label'indan `layer:*` al.

### Adim 5: Etkilenen Katmanlari Belirle

Degisen dosyalarin dizinlerine bakarak katmanlari belirle:

```bash
git diff --name-only develop..HEAD
```

- `apps/backend/` -> `layer:backend`
- `apps/ios/` -> `layer:ios`
- `apps/agent/` -> `layer:agent`
- `infra/` -> `layer:infra`
- `docs/` -> `layer:docs`
- `shared/` -> birden fazla katmani etkileyebilir

### Adim 6: Handoff Dosyalarini Oku

Pipeline tipine gore handoff dosyalarini oku (varsa):

```bash
# Architect handoff (full pipeline)
cat docs/pipeline/f<FAZ>/<slug>-architect.handoff.md 2>/dev/null

# Developer handoff (tum pipeline'lar)
cat docs/pipeline/f<FAZ>/<slug>-developer.handoff.md 2>/dev/null

# Tester handoff (full + standard)
cat docs/pipeline/f<FAZ>/<slug>-tester.handoff.md 2>/dev/null

# Reviewer handoff (full)
cat docs/pipeline/f<FAZ>/<slug>-reviewer.handoff.md 2>/dev/null
```

Handoff dosyalarindan PR body icin bilgi cikar:
- Degisiklik ozeti
- Coverage bilgileri
- Review sonucu
- Pipeline durum tablosu

### Adim 7: Pipeline Tipini Belirle

Sirasiyla kontrol et:
1. `--pipeline` parametresi verilmisse onu kullan
2. Issue label'larindan al: `pipeline:full`, `pipeline:standard`, `pipeline:quick`
3. Handoff dosyalarindan cikar
4. Varsayilan: `standard`

### Adim 8: Scope Belirle

Etkilenen katmanlara gore commit scope belirle:
- Tek katman: `backend`, `ios`, `agent`
- Birden fazla katman: en cok degisen katman veya `backend,ios` formati

### Adim 9: PR Olustur

**Handoff dosyalari varsa** (pipeline icerisinde olusturulan PR):

```bash
gh pr create \
  --title "<type>(<scope>): <Feature Adi> #<ISSUE_NO>" \
  --body "$(cat <<'EOF'
## Ozet

<Issue title ve aciklama>

## Degisiklikler

<Degisen dosyalarin ozeti, handoff dosyalarindan alinir>

### Backend
- <degisiklik 1>
- <degisiklik 2>

### iOS
- <degisiklik 1>
- <degisiklik 2>

### Agent
- <degisiklik 1>

## Pipeline Durum

| Adim | Agent | Durum |
|------|-------|-------|
| Architect | architect | DONE / SKIPPED |
| Developer | developer | DONE |
| Tester | tester | DONE / SKIPPED |
| Reviewer | reviewer | DONE / SKIPPED |

## Coverage

| Platform | Coverage | Esik | Durum |
|----------|----------|------|-------|
| Backend | X% | 80% | PASS/FAIL |
| iOS | X% | 70% | PASS/FAIL |
| Agent | X% | 80% | PASS/FAIL |

## Test

- Backend: X test, Y basarili, Z basarisiz
- iOS: X test, Y basarili, Z basarisiz
- Agent: X test, Y basarili, Z basarisiz

## Handoff Dosyalari

- `docs/pipeline/f<FAZ>/<slug>-architect.handoff.md`
- `docs/pipeline/f<FAZ>/<slug>-developer.handoff.md`
- `docs/pipeline/f<FAZ>/<slug>-tester.handoff.md`
- `docs/pipeline/f<FAZ>/<slug>-reviewer.handoff.md`

---
Generated by RafRaf AI Pipeline
EOF
)" \
  --base develop \
  --label "agent:pipeline" \
  --label "phase:f<FAZ>" \
  --label "layer:<KATMAN>" \
  --label "pipeline:<TIP>" \
  --repo atknatk/rafraf
```

**Handoff dosyalari yoksa** (pipeline disinda olusturulan PR): Pipeline Durum ve Coverage tablosunu ATLA, sadece Summary + Changes bolumleri goster:

```bash
gh pr create \
  --title "<type>(<scope>): <Feature Adi> #<ISSUE_NO>" \
  --body "$(cat <<'EOF'
## Ozet

<Issue title ve aciklama>

## Degisiklikler

<Degisen dosyalarin ozeti>

---
Generated by RafRaf AI Pipeline
EOF
)" \
  --base develop \
  --label "phase:f<FAZ>" \
  --label "layer:<KATMAN>" \
  --repo atknatk/rafraf
```

**Coverage verileri**: Tester handoff dosyasindan alinir (`docs/pipeline/f<FAZ>/<slug>-tester.handoff.md`). Handoff yoksa `/verify` skill'ini calistirarak coverage al.

Birden fazla katman etkileniyorsa her biri icin ayri label ekle:
```bash
--label "layer:backend" --label "layer:ios"
```

Draft PR olusturulmak isteniyorsa:
```bash
--draft
```

### Adim 10: Issue Label Guncelle

```bash
gh issue edit <ISSUE_NO> --remove-label "status:in-progress" --add-label "status:review" --repo atknatk/rafraf
```

## Cikti

```
Pull Request Olusturuldu
========================
PR: #<PR_NO>
URL: https://github.com/<owner>/<repo>/pull/<PR_NO>
Branch: <CURRENT_BRANCH> -> develop
Issue: #<ISSUE_NO>
Pipeline: <TIP>
Labels: agent:pipeline, phase:f<FAZ>, layer:<KATMAN>, pipeline:<TIP>

Sonraki adimlar:
  1. CI kontrollerinin gecmesini bekleyin
  2. agent:pipeline label'li PR'lar CI sonrasi otomatik merge edilir
  3. Manuel review gerekiyorsa reviewer atanir
```

## Hata Yonetimi

| Hata | Aksiyon |
|------|---------|
| Feature branch formatinda degil | Uyari goster, devam etmeyi sor |
| 0 commit | Hata, "en az 1 commit gerekli" |
| Push basarisiz | Pull --rebase sonrasi tekrar dene |
| PR zaten var | Mevcut PR URL'ini goster |
| Issue bulunamadi | Issue numarasiz PR olustur (label'siz) |
| Label bulunamadi | Label olusutur (`gh label create`) |

## Label Yonetimi

Gerekli label'lar yoksa otomatik olustur:

```bash
# Label var mi kontrol et, yoksa olustur
gh label create "agent:pipeline" --description "Pipeline tarafindan olusturuldu" --color "0E8A16" --repo atknatk/rafraf 2>/dev/null || true
gh label create "phase:f<FAZ>" --description "Faz <FAZ>" --color "1D76DB" --repo atknatk/rafraf 2>/dev/null || true
gh label create "layer:<KATMAN>" --description "<KATMAN> katmani" --color "D93F0B" --repo atknatk/rafraf 2>/dev/null || true
gh label create "pipeline:<TIP>" --description "<TIP> pipeline" --color "FBCA04" --repo atknatk/rafraf 2>/dev/null || true
```
